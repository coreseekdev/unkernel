# x86-64 CPU (src/x86_64)

The x86-64 guest CPU for the browser/Node branch (HANDOFF.md). It is a
reference interpreter only so far; the decoded-op tier and wasm JIT come
after the kernel UAPI (HANDOFF phase 4). The x86-64 kernel user ABI is
`kernel/patches/linux/0056-wasm-run-x86-64-user-space.patch`, selected
with `CONFIG_WASM_USER_X86_64` (`KW_USER_ISA=x86_64 kernel/build.sh
kernel`; AArch64 stays the default). Build-time selection:
`-Dkw-user-isa=x86_64` installs its objects as the primary `lib/libkwemu.a`,
`lib/kwemu.o` and `bin/kwemu-harness.wasm`; the AArch64 objects stay under
`lib/aarch64/` and `bin/aarch64/`. The default build is still AArch64.

## Layout

| File | Covers |
| --- | --- |
| `src/x86_64/state.zig` | `struct kw_regs` layout (Linux `user_regs_struct` words then MXCSR and XMM0-15 as `[2]u64`), RFLAGS bits, `Priv` in kwemu's opaque area |
| `src/x86_64/decode.zig` | prefixes/REX, ModRM/SIB, immediates, opcode routing into `Insn`; an unknown encoding is `error.Illegal`, never a no-op |
| `src/x86_64/exec.zig` | semantics: integer baseline, string ops, atomics, flags, SSE2, SYSCALL/CPUID/RDTSC, precise faults; x87 raises #UD |
| `src/x86_64/run.zig` | C ABI (`kw_cpu_init`, `kw_run`, ...) and the reference run loop |
| `src/x86_64/machine.zig` | unit-test machine (flat Sv48 tables, raw code) |
| `src/x86_64/harness*.zig` | mini-kernel: ELF loader and ~25 x86-64 Linux syscalls, native and wasm64 |
| `test/guest/x86_64/` | static musl guests (integer, FP, SSE2, strings, libc startup) |
| `test/x86-64-test.mjs` | runs the guests native and wasm64, and against qemu-x86_64 when it is on PATH |

## Rules

- The same contract as the A64 side: page tables are Sv48 (never x86
  PML4), the emulator never writes PTEs, A=0/D=0 is a kernel fault, and
  every flush hook behaves as `include/kw_emu.h` describes.
- An instruction that faults has no architectural effect. Read every
  operand and do every faulting access before writing registers, flags or
  memory; for a read-modify-write do the store before the flags/register
  update (`push` stores before moving rsp, `pop` commits rsp last). String
  instructions may keep the progress of completed iterations.
- No u128 shifts, multiplies or divisions in code that reaches the wasm
  object: they become `__lshrti3`/`__multi3` imports the kernel does not
  link. XMM registers are two u64 halves; lane helpers go through u64
  arithmetic (`exec.zig`, Lane views). `test/a64-test.mjs` checks the
  same rule for A64; `test/x86-64-test.mjs` checks the x86-64 object.
- `SYSCALL` already set rcx (return rip) and r11 (flags) and leaves rip
  past the instruction; the kernel returns with `rax` set.
- Do not advertise an extension in CPUID before its semantics exist
  (AVX/AVX2, SSSE3/SSE4 and the string instructions are not advertised).
  x87 is decoded only far enough to be a precise #UD; long double needs a
  later x87 implementation.
- RFLAGS is computed eagerly; the lazy/deferred flag design of a future
  tier must materialise it at every fault, helper, interrupt and block
  exit.

## Tests

```sh
zig build test-x86-64          # native unit tests
node test/x86-64-test.mjs zig-out   # static guests, native + wasm64 (+ qemu-x86_64)
zig build -Dkw-user-isa=x86_64      # x86-64 wasm64 object and harness as primary
```

`zig build test` runs the x86-64 unit tests, guests and wasm64 harness as
part of the ordinary suite. The wasm64 runners need Node 24 (Node 22
rejects the table64 modules).

The x86-64 kernel is `KW_USER_ISA=x86_64 kernel/build.sh kernel`
(`vendor/build/kernel-x86_64/vmlinux`; `vmlinux32.wasm` is lowered with
wasm-opt). A static x86-64 init boots; Alpine's dynamic loader and the
static BusyBox `ash` applet path still have failures (HANDOFF, Current
state).
